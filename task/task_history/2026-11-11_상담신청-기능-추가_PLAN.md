## 1. 요약

- 호스팅은 지시대로 **Cloudflare Pages**를 쓰고, 서버 기능은 같은 프로젝트의 **Pages Functions**(Workers 런타임)로 만듦
- 저장은 **Cloudflare D1**(SQLite 기반, 파일 1개짜리 DB와 같은 개념). 별도 DB 서버 없음
- 이메일은 **Cloudflare Email Routing의 메일 보내기(send_email)** 를 1순위로, 도메인이 없으면 **Resend 무료 요금제**를 2순위로 씀
- 관리자 페이지 로그인은 직접 만들지 않고 **Cloudflare Access(Zero Trust 무료 요금제)** 로 `/admin`·`/api/admin` 앞을 막음. 허용한 이메일로 받은 일회용 코드로만 들어감
- 스팸 방지는 **Cloudflare Turnstile**(무료)
- 예상 운영비: **0원 + 도메인 비용(연 1~2만 원 수준, 도메인을 쓸 경우)**

## 2. 구성도

```
방문자 브라우저
  └ index.html (상담 신청 폼)
       │ POST /api/consult  (JSON + Turnstile 토큰)
       ▼
Cloudflare Pages Functions
  ├ functions/api/consult.ts ─ 검증 → D1 저장 → 이메일 발송 → 결과 응답
  └ functions/api/admin/*    ─ 목록·상세·상태 변경 (Access 인증 통과한 요청만)
       │                         │
       ▼                         ▼
   Cloudflare D1           이메일(send_email 또는 Resend)
   (consultations 테이블)   → 지정 수신 주소

관리자 브라우저
  └ /admin/ (Cloudflare Access 로그인) → /api/admin/* 호출
```

## 3. 방식 선택과 이유

### 3.1 저장소: D1 (권장)

| 방식 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| **D1** | SQL로 최신순 정렬·상세 조회·상태 변경이 쉬움. 무료 한도가 충분함. 저장 데이터 암호화(Cloudflare 기본) | Cloudflare에 묶임 | **채택** |
| Workers KV | 단순 | 목록·정렬이 불편, 쓰기 반영이 늦을 수 있음 | 제외 |
| R2에 JSON 파일 | 파일 형태 그대로 | 동시 저장 시 덮어쓰기 위험, 목록·검색을 직접 구현 | 제외 |

- 지시의 "파일 형태로 해도 된다"에 해당: D1은 SQLite 파일 기반이라 백업도 SQL 파일 1개로 내보낼 수 있음(`wrangler d1 export`)

### 3.2 이메일

| 방식 | 조건 | 비용 | 판단 |
| --- | --- | --- | --- |
| **Email Routing send_email** | Cloudflare에 연결된 **도메인 필요**. 받는 주소를 미리 인증(인증 메일 1회 클릭) | 무료 | **1순위** (수신자가 정해진 알림 메일에 딱 맞음) |
| Resend | 도메인 없이 쓰면 Resend 가입 이메일로만 발송 가능. 도메인 인증 시 제한 없음 | 무료 한도(월 3,000건 수준) | 2순위 |

- 받는 주소는 코드에 쓰지 않고 환경 변수 `CONSULT_TO_EMAIL`로 둠 → 추후 변경 시 Cloudflare 대시보드에서 값만 바꿈(Email Routing 방식이면 새 주소 인증 1회 필요)
- 무료 한도·요금은 작성 시점 지식 기준. 계정 만들 때 다시 확인함

### 3.3 관리자 인증: Cloudflare Access (권장)

- 비밀번호 저장·세션·로그인 화면을 만들 필요가 없어 보안 구멍이 적음
- 허용 이메일 목록(예: 김광열 팀장, 관리자 1~2명)만 일회용 코드로 로그인
- Functions에서도 Access가 붙여 주는 인증 토큰(`Cf-Access-Jwt-Assertion`)을 한 번 더 검증함(이중 확인)
- 무료 요금제 50명까지

### 3.4 대안 (참고)

- **Google Apps Script + Google 스프레드시트**: 비용 0원, 시트가 곧 관리자 화면. 다만 지시한 "관리자 페이지"와 상태 표시 화면을 따로 만들기 어렵고, 개인정보가 개인 구글 계정 시트에 쌓여 권한 관리가 느슨해지기 쉬움 → 권하지 않음

## 4. 기능별 구현 내용

### 4.1 문의 내용 500자 제한 (지시 1)

- `<textarea maxlength="500">` + 입력란 아래 글자 수 표시(`123 / 500`)
- 서버에서도 500자 넘으면 거부(브라우저 우회 방지)

### 4.2 개인정보 동의 확인 (지시 2)

- 해석이 두 가지라 확인 필요(6장 질문 2)
  - (가) **체크하지 않으면 신청되지 않게** 막고 안내 문구 표시 — 권장
  - (나) 처음부터 체크된 상태로 둠 — 개인정보보호법 가이드상 동의 기본 체크는 피해야 해서 권하지 않음
- (가)로 갈 경우: 지금 `required`(브라우저 기본 말풍선)에 더해 체크 안 하고 누르면 "개인정보 수집·이용에 동의해 주세요" 문구를 폼 안에 표시, 서버에서도 `agree=true` 아니면 거부

### 4.3 상담 신청 이메일 발송 (지시 3)

- 제출 흐름: 입력 검증 → Turnstile 확인 → **D1에 먼저 저장** → 이메일 발송 → 응답
  - 이메일이 실패해도 신청은 저장되어 있으므로 사용자에게는 접수 완료로 안내하고, DB에 `email_status = failed`로 남겨 관리자 화면에 표시
- 메일 형식(HTML + 텍스트 대체본)
  - 제목: `[상담신청] 홍길동 · 40대 · 연금, 보장분석`
  - 본문: 신청 일시(KST), 성함, 연락처(눌러서 전화 걸기 링크), 연령대, 상담 분야, 문의 내용, 관리자 페이지 상세 링크를 표로 정리
  - 입력값은 모두 HTML 이스케이프(메일 내 스크립트·링크 삽입 방지)
- 제출 후 화면: 버튼 "신청 중…" 비활성 → 성공 시 폼 자리에 "상담 신청이 접수되었습니다" 안내, 실패 시 오류 안내와 전화·문자 대체 안내
- 지금의 `sendForm()`(문자 앱 열기)은 제거하고 위 흐름으로 교체 예정(6장 질문 3). 상단의 전화·문자 바로가기 링크는 그대로 둠

### 4.4 네이버 지도 링크 (지시 4)

- 상담신청 섹션의 `📍 지점 / 현대해상 경인지역 구월지점` (`index.html` 546행, 지금은 `href` 없는 `<a>`)에 네이버 지도 주소 연결
- `target="_blank" rel="noopener noreferrer"` 로 새 탭 열기
- 주소는 네이버 지도 플레이스 고유 URL(`https://map.naver.com/p/entry/place/...`)이 가장 정확함 → 받거나 찾아서 확인 필요(6장 질문 5). 못 구하면 검색 URL(`https://map.naver.com/p/search/현대해상 구월지점`)로 대신함
- 푸터·소개 영역의 "구월지점" 문구는 지시 범위가 아니라 링크하지 않음

### 4.5 관리자 페이지와 저장 (지시 5)

**DB 테이블 `consultations`**

| 컬럼 | 내용 |
| --- | --- |
| id | 정수, 자동 증가 |
| created_at | 신청 일시(UTC 저장, 화면에는 KST로 표시) |
| name / phone / age_group | 성함 / 연락처 / 연령대 |
| interests | 상담 분야(쉼표 구분 문자열) |
| message | 문의 내용(500자 이내) |
| status | `planned`(상담 예정) / `done`(상담 완료) |
| status_updated_at | 상태 바꾼 일시 |
| email_status | `sent` / `failed` |

- 인덱스: `created_at DESC`
- 스키마는 `migrations/0001_init.sql`로 관리(`wrangler d1 migrations apply`)

**관리자 화면 `/admin/`** (정적 HTML 1개 + JS, 사이트와 같은 색 변수·Pretendard)

- 목록(지시 5-1, 5-2, 5-5): 최신 신청이 위. 열은 신청 일시 · 성함 · 연락처 · 연령대 · 상담 분야 · 상태 배지. 20건씩 더 보기
- 상세(지시 5-3, 5-5): 목록 행을 누르면 상세. 모든 항목 + 신청 일시 + 메일 발송 결과
- 상태 표시(지시 5-4): 상세에서 [상담 예정] / [상담 완료] 버튼으로 바꿈, 바꾼 일시 표시
- 모바일 폭에서는 목록을 카드형으로 표시

**관리자 API** (모두 Access 인증 필수)

- `GET /api/admin/consultations?cursor=` 목록
- `GET /api/admin/consultations/:id` 상세
- `PATCH /api/admin/consultations/:id` 상태 변경 (`{ "status": "done" }`)

## 5. 보안·개인정보 대책

1. **배포 폴더 분리(중요)**: 지금은 저장소 최상위에 `index.html`이 있어, 최상위를 그대로 배포하면 `AGENTS.md`·`CLAUDE.md`·`task/`(키 파일 `task/.env.naver` 포함)까지 공개됨 → 공개 파일만 `public/`으로 옮기고 배포 폴더를 `public/`으로 지정
2. **입력 검증은 서버에서 다시**: 성함 1~30자, 연락처 숫자·하이픈 형식, 연령대·상담 분야는 정해진 값만, 문의 500자, 동의 필수
3. **스팸·대량 신청 방지**: Turnstile(사람 확인, 보통은 클릭 없이 통과) + 같은 IP 짧은 시간 반복 신청 제한
4. **XSS 방지**: 관리자 화면은 `textContent`로만 표시(`innerHTML` 사용 안 함), 메일 본문은 이스케이프
5. **관리자 접근**: Cloudflare Access + Functions에서 토큰 재검증. 관리자 페이지는 검색엔진 수집 차단(`noindex`, `robots.txt`)
6. **비밀 값 관리**: 수신 이메일·API 키·Turnstile 비밀키는 Cloudflare 환경 변수/시크릿으로만 두고 저장소에 커밋하지 않음. `.gitignore`에 `.dev.vars`, `.env*`, `.wrangler/` 추가
7. **로그에 개인정보 남기지 않음**: 오류 로그에는 신청 id만
8. **전송 구간 암호화**: Cloudflare 기본 HTTPS. 저장 데이터는 Cloudflare가 기본 암호화

**법·심의 확인이 필요한 부분 (개발 범위 밖, 사용자 확인 필요)**

- 서버에 개인정보를 저장하게 되므로 **개인정보 처리방침** 게시가 필요할 수 있음
- Cloudflare·메일 서비스는 해외 사업자라 **처리위탁·국외 이전 고지**가 필요할 수 있음
- 동의 문구의 `보유 기간: 상담 완료 후 [기간 입력]` 값이 정해져야 하며, 기간이 지난 신청을 지우는 방법(관리자 삭제 버튼 또는 자동 삭제)도 정해야 함
- 위 내용은 현대해상 준법감시(광고 심의) 담당 확인을 권함

## 6. 결정이 필요한 사항

1. **도메인**: 쓸 도메인이 있는지, 없으면 구매할지 → 메일 방식(Email Routing / Resend)과 관리자 주소가 정해짐. 도메인 없이 `*.pages.dev`만 쓰면 Resend + 가입 이메일 수신으로 감
2. **동의 체크 해석**: (가) 체크 안 하면 신청 막기(권장) / (나) 기본 체크
3. **문자 앱 열기 제거**: 신청서 제출 시 지금처럼 문자 앱을 여는 동작을 없애고 이메일·저장으로 바꿀지(권장: 제거)
4. **개인정보 보유 기간과 삭제**: 기간 값, 관리자 삭제 버튼·자동 삭제 필요 여부(지시에는 없음)
5. **네이버 지도 주소**: 구월지점 플레이스 URL을 줄 수 있는지(없으면 찾아서 확인 후 사용)
6. **관리자 허용 이메일**: Cloudflare Access에 등록할 관리자 이메일 목록
7. **새 신청의 기본 상태**: `상담 예정`으로 시작(가정). 별도 "신규/미확인" 상태가 필요한지
8. **배포 방식**: GitHub 연결 자동 배포 / 내 PC에서 `wrangler pages deploy` 직접 배포

| 6 | Turnstile·반복 신청 제한 | 토큰 없이 API 직접 호출 시 거부 |
| 7 | Cloudflare 설정·배포: Pages 프로젝트, D1 생성·마이그레이션, 환경 변수, Access 정책, (도메인 연결·Email Routing) | 실제 주소에서 신청 → 메일 도착 → 관리자 화면 확인, 로그인 안 한 브라우저로 `/admin`·`/api/admin` 접근 차단 확인 |
| 8 | 문서 갱신: `CLAUDE.md`(구조·명령·확인 방법), `README.md` 배포·운영 방법 | 문서대로 처음부터 로컬 실행 가능 |

- 1~6단계는 로컬(`wrangler pages dev` + 로컬 D1)에서 완료 가능. 7단계는 Cloudflare 계정 작업이 있어 사용자와 함께 진행
- `CLAUDE.md`의 "빌드 도구·패키지 매니저 없음, 라이브러리 추가 금지" 기준과 달라지므로(wrangler, Turnstile 스크립트 추가), 승인 시 함께 갱신함
